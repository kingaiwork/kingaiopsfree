# KINGAI OPS — Commercial Editions

KINGAI OPS follows a **free-to-use proprietary core + paid scale/governance/security** model.

The Free/Core edition is intended to remain genuinely useful. Paid editions focus on fleet scale, collaboration, advanced security, hosted coordination and enterprise integration rather than artificially disabling basic local safety.

## Edition direction

| Edition | Best for | Direction |
|---|---|---|
| **Core / Free** | individual developers, VPS owners, homelab | local-first management, visibility, backups, audit and security foundation |
| **Pro** | developers and small fleets | hosted coordination, multi-node operations, advanced runbooks and AI-assisted operations |
| **Business** | teams, agencies, MSPs | approvals, policy packs, RBAC, staged operations and centralized audit |
| **Security** | security-conscious production teams | advanced KINGAI Sentinel, runtime integrations, incident correlation and containment |
| **Enterprise** | larger organizations | private control plane, SSO, SIEM, advanced governance, release channels and support |

Exact pricing and feature limits should be published only when the corresponding production services are generally available.

## Customer problems

### Individual operators

Common problems:

- too many separate server tools;
- fear that updates will break production;
- inconsistent backups;
- no dedicated SRE/security team;
- reluctance to depend on an external AI API for basic management.

KINGAI OPS direction:

- one local management surface;
- deterministic Core Mode;
- safer operational controls;
- health, drift and audit visibility;
- optional intelligence rather than mandatory AI dependence.

### Agencies and MSPs

Common problems:

- many customer servers across mixed providers/distributions;
- repeated maintenance work;
- inconsistent operational standards;
- difficulty proving what changed and when.

Commercial direction:

- tenant/fleet organization;
- reusable policy/runbook templates;
- staged operations;
- approvals and audit;
- commercial MSP/OEM integration.

### Product companies

Common problems:

- developers share infrastructure duties;
- operational incidents interrupt product work;
- security tools and operations tools do not share context;
- production changes lack consistent verification/rollback discipline.

Commercial direction:

- Fleet and team workflows;
- centralized policy and audit;
- maintenance windows;
- verified operational transactions;
- Sentinel incident context.

### AI infrastructure teams

Common problems:

- agents need real infrastructure tools;
- unrestricted shell access is difficult to govern;
- model/provider outages should not disable core infrastructure operations.

Commercial direction:

- typed operational tools;
- local authority boundary;
- optional local models;
- governed cloud provider routing;
- specialized SRE/Security/Database/Recovery agents.

## Business positioning

KINGAI OPS should not be marketed as “a server panel with a chatbot.”

The stronger product story is:

> **Infrastructure that becomes easier to operate as it grows—without giving up control.**

The differentiation is expected to come from the combined system:

- local-first node authority;
- policy/risk/approval semantics;
- controlled execution and verification;
- rollback/recovery discipline;
- unified operations + security event model;
- Linux compatibility knowledge;
- Fleet coordination;
- optional AI above—not instead of—the authority layer.
